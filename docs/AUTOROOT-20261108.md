## 1. Magisk 闪退修复

现象：`com.topjohnwu.magisk`（canary 构建 `e8a58776`，10-24 安装）点开即崩，
栈固定为 `UIActivity.getBinding` → `MainActivity.onResume` 的
`UninitializedPropertyAccessException`。

处理：
1. 卸载 canary 构建。
2. 安装官方稳定版 `Magisk-v30.7.apk`。荣耀安装器以"未查询到此应用的 ICP 核准信息"
   拦截常规安装；用 `pm install-create -i android` 会话方式绕过（`sess-install.sh`）。
3. 安装后冷启动正常，进程存活，无 FATAL，主界面正常显示（Zygisk: No / Ramdisk: Yes）。
   通知权限已授予。

结论：闪退是该 canary 构建自身的生命周期缺陷，与 root 会话无关；
官方 v30.7 在同一环境下正常。

## 2. 手机端 root 状态检查（应用内，已打通）

- `ai.mofa.honorautoroot`（appId 10292）启动即检查 `/data/local/tmp/su -c id`。
- su daemon 升级：socket 0666；`SO_PEERCRED` 允许
  root / shell / `/data/local/tmp/honor_su_caller_uid` 文件中记录的 UID。
- 实测：应用内 `su -c id` 返回 `uid=0(root)`，应用正确报告
  `root already active; exploit not run`（已有 root 不重复打）。

日志（logcat `HonorAutoRoot`）：

```text
checking root availability
su -c id rc=0 out=uid=0(root) gid=0(root) groups=0(root) context=u:r:shell:s0
status: root already active; exploit not run
```

## 3. 应用沙箱内直接提权：不可行（实测）

以 `--ez run_root true` 启动应用，在无 root 状态下让其在自身进程内执行
43499 standalone 载荷（`u:r:untrusted_app:s0`，uid 10292）：

```text
startup pid=13888 uid=10292 attr=u:r:untrusted_app:s0:... enforce=unreadable
slide ktext atrace start rc=32512
native rc=255 root=false
```

失败在第 0 步：应用域无法执行 `atrace`（exec 被拒）。后续依赖的
tracefs 读取（slide KASLR 投票）、`sched_setattr`、seccomp 面同样不可用。
SELinux enforce 状态在应用域也不可读（`enforce=unreadable`）。

结论：43499 载荷的 KASLR 校准链在应用沙箱内第一步即失败。
要在应用内提权，需要 GhostLock 级别的完整适配
（W1/W2/W3 三段写 + rss_stat 触发替代 atrace + seccomp 绕过），
当前仓库载荷不具备，也不是小改动能补的。

## 4. BOOT_COMPLETED 开机自动恢复：被系统拦截

重启后 2 分钟内无任何 `HonorAutoRoot` 日志、无应用进程、无 payload 同步日志：
开机广播未送达（荣耀自启动管理对"未经安全审核"的第三方应用默认拦截）。
需要用户在设置中手动允许自启动，或系统级方案，当前无法自动化。

## 5. 本轮 exploit 成功率

8 次发射：2 成功，4 次 panic 重启（2 次死在 slide，2 次死在恢复写之后），
2 次无重启失败（恢复写阶段退出）。设备高负载时段成功率明显下降；
空闲时段（11-05、21:09）为 3/3。结论：竞争成功率对系统状态敏感，
避免在负载高时发射。
